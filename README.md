# ubx-sdk-kubernetes

Typed bindings for Kubernetes (`[dynamic_providers.kubernetes]`,
OpenAPI/Swagger-sourced via `ubx-provider-dynamic`), generated by
[ubx](https://github.com/ubiquex/ubiquex) (`ubx sdk gen`), for all three
SDK languages in one combined repo:

- [`sdk/go/`](sdk/go/) — Go bindings, module `github.com/ubiquex/ubx-sdk-kubernetes/sdk/go`
  (a subdirectory Go module, tagged `sdk/go/vX.Y.Z`)
- [`sdk/typescript/`](sdk/typescript/) — TypeScript bindings, published to JSR as
  [`@ubx/sdk-kubernetes`](https://jsr.io/@ubx/sdk-kubernetes)
- [`sdk/python/`](sdk/python/) — Python bindings, published to PyPI as
  [`ubx-sdk-kubernetes`](https://pypi.org/project/ubx-sdk-kubernetes/)
  (imported as `ubx.kubernetes.*`, a real PEP 420 namespace package)

One package per Kubernetes API group boundary (`apps/`, `core/`, ...),
one file per resource type, in every language.

## Install

```
go get github.com/ubiquex/ubx-sdk-kubernetes/sdk/go
npm install @ubx/sdk-kubernetes
pip install ubx-sdk-kubernetes
```

## v1.0.0: source change, not just a version bump

Every version before `1.0.0` was generated from the `hashicorp/kubernetes`
Terraform provider. As of `1.0.0`, this repo is generated from
Kubernetes' own real OpenAPI/Swagger API description
(`[dynamic_providers.kubernetes]` in `ubiquex`), the source `ubx`
actually resolves and applies changes against today. The naming
generation is entirely different (`kubernetes_apps_deployment`, not
`kubernetes_deployment`) — there is zero real overlap by type name
between the old and new identifiers, confirmed by direct comparison,
not just asserted. The old identifiers are gone because they described
a schema `ubx` no longer uses.

`release-1.37` in the schema URL is a real, live Kubernetes branch, not
a tag — it can still receive content updates (patch backports) between
now and Kubernetes' next minor release. `VERSION` uses the same
content-hash scheme as `ubx-sdk-aws`/`ubx-sdk-datadog`/`ubx-sdk-github`:
a SHA-256 of the raw spec bytes, the fetch date, and the source URL.
Moving to a newer `release-1.NN` branch when Kubernetes ships one is a
separate, manual edit to `[dynamic_providers.kubernetes]`'s own
`schema_url` in `ubiquex` — `hash-watch.yml` here only detects content
drift within whichever branch is currently pinned, not a new branch
existing.

This repo-shaped-per-provider layout (UBI-138) supersedes the earlier
one-repo-per-(provider,language) convention (UBI-98/UBI-103) — matches
the real Pulumi precedent this project cites (`pulumi/pulumi-kubernetes`'s
own `sdk/go/`, `sdk/python/`, `sdk/nodejs/` structure). Package names on
every registry are unchanged; only Go's module path changed, because a
subdirectory Go module requires it.

Every file except each language's own `doc.{go,ts}` / `__init__.py` is
generated — do not hand-edit; re-run `ubx sdk gen` after the source
schema changes.

Depends on the shared runtime: [ubx-sdk-go](https://github.com/ubiquex/ubx-sdk-go) (Go),
[`jsr:@ubx/sdk`](https://jsr.io/@ubx/sdk) (TypeScript),
[`ubx-sdk`](https://pypi.org/project/ubx-sdk/) (Python, imported as `ubx_sdk`).
